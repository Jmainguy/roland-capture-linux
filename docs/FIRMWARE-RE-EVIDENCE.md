# Device firmware v1.51 reverse-engineering evidence

This ledger records reproducible static evidence from the user-supplied Roland
device updater. The updater is never executed or flashed, and proprietary
firmware is not committed or redistributed.

## Frozen input

- `octa_sys_v151.zip`: SHA-256
  `a259fcca8939fe4d5310c95e4c5baf264c8f273745329a9fb93f20cc61a2f99d`.
- `UpdOcta.dat`: 1,048,576 bytes; SHA-256
  `fc82e9c516d6661caffa151b0f818828e96b679df36dee217c1e3944c39cdad4`.
- Ghidra 12.1.3 with the open-source `ghidra-blackfin` processor module,
  locally ported to the current loader API.

The durable Ghidra projects live under `tmp/device-firmware-v151/ghidra/`.
Generated, non-proprietary listings and address evidence live under
`evidence/firmware-v151/`; reusable export scripts live in `tools/ghidra/`.
The decoded proprietary runtime stays under `tmp/` and is not redistributed.

## Reproduction notes

Import file bytes starting at offset `0x20` with the Blackfin language at base
address `0x20000020`. Seed entries `0x20000020`, `0x20004100`, and
`0x20020100` with `SeedFirmwareEntrypoints.java`, then run normal analysis.
The upstream Blackfin boot-stream loader recognizes the wrapper but stops at
its final/ignore record and therefore does not map Roland's appended flash
image; the raw mapping above preserves that image and follows the header's
declared target.

Static conclusions are correlated with automatic attached-device readback when
that is safe and available; they do not depend on further manual front-panel
experiments. In particular, readable text fragments inside encoded resource
data are not accepted as command or setting evidence. Analog Devices documents
the general `bfrom_MemBoot` pattern for selecting a boot stream at an arbitrary
flash address, but the updater's observed `0xffa0811c` call lies in L1
instruction SRAM rather than the standard `0xef000008` ROM entry. It is
therefore identified from its implementation as the bank's LZSS decoder, not
mislabelled as the ROM API.
